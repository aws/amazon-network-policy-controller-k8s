# AGENTS.md

Guidance for coding agents and human contributors working in this repository.

## What this is

The Amazon Network Policy Controller watches NetworkPolicy, ApplicationNetworkPolicy (ANP) and ClusterNetworkPolicy (CNP) objects, resolves them against pods, namespaces and Services, and writes the result as PolicyEndpoint (PE) and ClusterPolicyEndpoint (CPE) objects. The node agent ([aws-network-policy-agent](https://github.com/aws/aws-network-policy-agent)) reads those objects and enforces them with eBPF. The controller never touches a node: what it writes into a PE is exactly what the agent enforces.

- `cmd/main.go`: entry point. Loads flags, checks the `amazon-vpc-cni` configmap (`--enable-configmap-check`), ensures the CRDs exist, then starts the manager.
- `internal/controllers/policy_controller.go`: the one reconciler. A namespaced request reconciles both the NetworkPolicy and the ANP with that name; a cluster-scoped request reconciles the CNP.
- `internal/eventhandlers/`: policy, pod, namespace and Service handlers. Pod, namespace and Service events are mapped to the policies they affect and sent through a channel as generic events, which the policy handler enqueues after `--pod-update-batch-period-duration`.
- `pkg/resolvers/`: `endpoints.go` and the ANP/CNP resolvers turn a policy into ingress, egress and pod-selector endpoints; `policies_for_*.go` and `policy_tracker.go` find the policies a pod, namespace or Service event affects.
- `pkg/policyendpoints/`: computes the PE/CPE create, update and delete lists, bin-packs rules into chunks of `--endpoint-chunk-size`, and writes them.
- `pkg/config/`: flags and the manager's cache options (pod and Service transforms, pod field selector).
- `pkg/crd/`: the embedded CRDs (`crds.yaml`, generated by `make prepare-embed`) and the manager that creates missing CRDs at startup.
- `api/v1alpha1/`: the CRD types. The node agent keeps its own copy of the PE and CPE types.
- `charts/amazon-network-policy-controller-k8s/`: the Helm chart. Its RBAC and flags are maintained by hand.

## Build and test

- `make build`: runs `prepare-embed`, `manifests`, `generate`, `fmt` and `vet`, then builds `bin/controller`. The Go version comes from `go.mod` (`go 1.26.9`); `.go-version` picks the image used by `govulncheck` in CI.
- `make test`: same generators, then `go test ./...` with envtest assets (`internal/eventhandlers/cache_readonly_test.go` starts a real API server through envtest). For one package: `go test ./pkg/resolvers/...`.
- `make check-format` (needs `goimports`) and `make vet`: the code checks CI runs.
- `make manifests` regenerates `config/crd/bases` and `config/rbac/role.yaml` from kubebuilder markers. `make prepare-embed` rebuilds `pkg/crd/crds.yaml` from `config/crd/bases`. Commit the regenerated files with the change that caused them.
- `make run-cyclonus-test CLUSTER_NAME=<name>` runs `scripts/run-cyclonus-tests.sh` against a live cluster. `make run-startup-scale-test` runs the kwok startup scale test in `test/e2e/startup` (build tag `e2e`) against the cluster in the current kubeconfig.

CI:

- `.github/workflows/pr-tests.yaml` runs on PRs to `main`: `check-format`, `vet`, `make build`, `make test`, `make docker-buildx`, a deprecated-apiGroups check, `govulncheck`, and `make check-deps CHECK_DEPS_STRICT=true`, which fails when a direct dependency in `go.mod` is out of date.
- A PR comment `/test e2e <full-sha>` from a user with write access runs `pr-e2e-tests.yaml`: it builds the PR image, creates IPv4 and IPv6 EKS clusters, runs cyclonus on both and the startup scale test on IPv4 only. It takes several hours.

## Hard rules

- **The cache is shared.** The policy reference resolver reads with `client.UnsafeDisableDeepCopy`, so the objects it reads and returns belong to the informer cache. Never write to them or to anything reachable from them; `DeepCopy` first. `TestPolicyReferenceResolverDoesNotMutateCache` checks this. Do not add `UnsafeDisableDeepCopy` to a read whose result is later modified, such as the PE lists in `pkg/policyendpoints`.
- **The cache is stripped.** Pods and Services are cached through `StripDownPodTransformFunc` and `StripDownServiceTransformFunc`, and pods through a field selector that drops terminal and unscheduled pods. A field the transform drops reads as its zero value, with no error. To read a new field, add it to the transform and its test.
- **Every read type needs an informer.** The cache sets `ReaderFailOnMissingInformer: true`. A `Get` or `List` of a type missing from `BuildCacheOptions` fails at runtime.
- **List PEs by the field index.** Use `client.MatchingFields{IndexKeyPolicyReferenceName: name}`. PEs carry no labels, so a label selector matches nothing.
- **The PE is an API with a second reader.** A change to what a PE or CPE contains changes what every node enforces. A change to a PE/CPE type or CRD must also land in the node agent's copy of the types, and must work with the agent version already on the nodes.
- **CRDs are created, never updated.** The CRD manager only creates a missing CRD. A schema change does not reach a cluster where the CRD already exists. The chart ships only the PolicyEndpoint CRD.
- **Event handlers do not retry.** A resolver error in a pod, namespace or Service handler is logged and the event is dropped. Keep handler work cheap and read only from the cache: it runs inline for every pod, namespace and Service event.
- **Flags.** Treat a new flag as a one-way door; prefer no flag. A new flag also goes in the chart's `deployment.yaml` and `values.yaml`.
- **RBAC in two places.** A new kubebuilder RBAC marker regenerates `config/rbac/role.yaml`; the chart's `templates/rbac.yaml` must be updated by hand to match.
- **Logging.** The default level is info. A log line that fires per pod, per endpoint or per event belongs at `V(1)`, or batched into one line per reconcile.
- **Comments.** Describe current behavior and why, not change history.

## Review checklist

`docs/review-guide.md` has the full checklist: cache and API contracts, the PE write path, precedents to reuse, and recurring review themes, each with code citations and a way to check it. Read the sections that match the files a change touches before you open or review a PR. Each item is tagged `[blocking]` or `[advisory]`. When reviewing, report a finding as blocking only when its own impact meets the blocking bar in the guide's section 1, not because the guide item is tagged blocking; list blocking findings first and keep advisory ones brief.

[`docs/using-the-review-guide.md`](docs/using-the-review-guide.md) explains how to use AGENTS.md and the review guide in your workflow.
